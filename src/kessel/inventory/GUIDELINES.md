# Inventory Module Guidelines

This module provides the `ClientBuilder` fluent API for constructing gRPC clients
and organizing version-specific service stubs.

## Editable Files

- `__init__.py` -- `ClientBuilder` base class and `client_builder_for_stub()` factory
- `v1/__init__.py` -- `ClientBuilder` for `KesselInventoryHealthServiceStub`
- `v1beta2/__init__.py` -- `ClientBuilder` for `KesselInventoryServiceStub`

Everything else (`*_pb2.py`, `*_pb2_grpc.py`, `*.pyi`) is generated by `buf generate`. Never edit generated files.

## ClientBuilder Pattern

### Factory Function

`client_builder_for_stub(stub_class)` returns a new `ClientBuilder` subclass with `_stub_class` set:

```python
ClientBuilder = client_builder_for_stub(KesselInventoryServiceStub)
```

Each version directory creates its own `ClientBuilder` this way. Users import from the version:

```python
from kessel.inventory.v1beta2 import ClientBuilder
```

### Fluent API

`ClientBuilder` uses method chaining via `typing.Self` return annotations:

```python
stub, channel = ClientBuilder(target).insecure().build()
stub, channel = ClientBuilder(target).oauth2_client_authenticated(creds).build()
stub, channel = ClientBuilder(target).authenticated(call_creds, channel_creds).build()
```

All builder methods (`insecure()`, `unauthenticated()`, `authenticated()`, `oauth2_client_authenticated()`) return `self`.

### Build Output

Both `build()` and `build_async()` return a `(stub, channel)` tuple. The channel must be closed by the caller:

- Sync: `with channel:` context manager
- Async: `async with channel:` context manager

### Channel Construction

| Method | Channel Type |
|---|---|
| `build()` | `grpc.insecure_channel` or `grpc.secure_channel` |
| `build_async()` | `grpc.aio.insecure_channel` or `grpc.aio.secure_channel` |

Do not mix sync and async channels. A channel from `build()` cannot be used with `await`.

### Credential Defaults

- No channel credentials provided: defaults to `ssl_channel_credentials()` (TLS) when `build()` or `build_async()` is called.
- `insecure()`: sets `insecure_channel_credentials()` and clears call credentials.
- `oauth2_client_authenticated()`: converts `OAuth2ClientCredentials` to gRPC call credentials via `oauth2_call_credentials()`.

### Validation

`_validate_credentials()` raises `ValueError` when call credentials are paired with `insecure_channel_credentials()`. Only `oauth2_client_authenticated()` calls this validation automatically. The `authenticated()` method does NOT validate credentials, so avoid manually pairing call credentials with insecure channel credentials when using `authenticated()`.

`__init__` raises `TypeError` for empty, None, or non-string targets.

### Keepalive Policy

Both `build()` and `build_async()` apply an HTTP/2 keepalive policy on every channel to prevent idle-timeout resets behind load balancers (Classic ELB, Istio gateway):

| Setting | Default | Purpose |
|---|---|---|
| interval | 45 seconds | Time of inactivity before sending a keepalive ping (under 60 s LB idle timeout) |
| timeout | 10 seconds | Time to wait for a ping ACK before closing the transport |
| permit_without_calls | `True` | Send pings even with no active RPCs |
| max_pings_without_data | 0 (internal) | No cap on pings without data frames (not exposed publicly) |

`build()` additionally sets `ChannelOptions.SingleThreadedUnaryStream = 1` for sync channels, reducing thread overhead for server-streaming RPCs. `build_async()` does not set this (async event loop handles it natively).

Consumers do **not** need to call `.keepalive()` to enable keepalive — it is always on.

#### Customising keepalive

Use `.keepalive()` with typed, named arguments to override individual settings. Omitted values retain their defaults. The method may be called more than once; each call updates only the supplied fields.

```python
from datetime import timedelta

stub, channel = (
    ClientBuilder(target)
    .insecure()
    .keepalive(interval=timedelta(seconds=30), timeout=timedelta(seconds=5))
    .build()
)
```

Disable pings when idle:

```python
stub, channel = (
    ClientBuilder(target)
    .insecure()
    .keepalive(permit_without_calls=False)
    .build()
)
```

Duration arguments must be positive `timedelta` values; `permit_without_calls` must be a `bool`. Invalid values raise `TypeError` or `ValueError`.

## Version Directories

| Directory | Status | Stub |
|---|---|---|
| `v1/` | Active | `KesselInventoryHealthServiceStub` (health checks) |
| `v1beta2/` | Active (current) | `KesselInventoryServiceStub` (main API) |
| `v1beta1/` | Deprecated | Do not extend. Entirely generated code. |

All new features use `v1beta2`. The `v1beta2` API uses a single generic service (`KesselInventoryService`) with `ReportResource`/`DeleteResource` instead of resource-specific services.

## Import Guard for Auth

The `OAuth2ClientCredentials` type is imported under `TYPE_CHECKING` only:

```python
from typing import Self, TYPE_CHECKING

if TYPE_CHECKING:
    from kessel.auth import OAuth2ClientCredentials
```

The actual import happens at runtime inside `oauth2_call_credentials()` in `kessel.grpc`. This pattern is required because auth dependencies are optional extras.

## Testing Patterns

- Test builder methods for correct internal state and method chaining (`result is builder`).
- Patch `kessel.inventory.insecure_channel_credentials` and `kessel.inventory.oauth2_call_credentials` at their import sites.
- Do not test `build()` or `build_async()` directly -- they create real gRPC channels.
- Tests are in `tests/test_client_builder.py`, grouped by builder method in test classes.

## Adding a New Service

1. Run `buf generate` to produce stubs in `src/kessel/<service>/<version>/`.
2. Create `src/kessel/<service>/<version>/__init__.py`:
   ```python
   from kessel.inventory import client_builder_for_stub
   from kessel.<service>.<version>.<stub_file>_pb2_grpc import <StubClass>
   ClientBuilder = client_builder_for_stub(<StubClass>)
   ```
3. The `ClientBuilder` inherits all auth/channel/TLS behavior from the base class.
